# 多脚本与共享地址

配置管理页右下角的“脚本库”集中维护名称和下载地址；配置编辑器通过“选择脚本”引用其中的脚本。也可粘贴/扫码添加地址，相同的规范化地址直接复用已有定义。

## 保存和复用

- 共享定义最多 100 个；单个配置最多引用 16 个，不允许重复引用。
- 每个配置独立保存顺序和启用开关。停用保留顺序，不下载、不执行。
- 脚本库条目在名称旁显示 **“N 个配置引用”** 徽标：只统计已保存配置，停用引用也计入，同一配置只计一次；未保存的编辑草稿、当前分类/收藏筛选和脚本运行次数都不影响。有引用时使用浅绿样式，0 引用使用浅灰样式但仍可编辑、选择和删除。窄屏、横屏和大字体下整枚徽标换到名称下方，文字保持单行不裁切。
- 选择窗口保持脚本库顺序，勾选不会将条目移到顶部；启停与上移/下移仅在配置编辑页的已选脚本卡片中调整。卡片复选框使用配置草稿恢复状态，避免同 ID 动态控件的视图状态覆盖停用设置。
- 脚本库的说明、新建/批量添加入口和脚本条目共用滚动区，标题与底部操作保持可见；大字体下“确认选择”可换行并撑高按钮。脚本编辑器的焦点滚动立即完成，避免横屏键盘调整高度后旧滚动动画再次裁切输入框。
- 已选脚本的移除图标只解除当前配置引用，随配置保存提交，脚本库及其它配置保持原样。管理页悬浮入口为竖排圆形图标，不透明度为 85%；闲置直径 39 dp，点按放大为 78 dp 并在图标下显示“脚本”或“配置”，再次点按执行，点击其它位置或闲置 3 秒自动收起。外部点击继续交给原控件处理。圆形随缩放收紧占位，右侧距边 10 dp、底部距边 12 dp。
- 修改共享地址会影响全部引用，刷新/重开时生效；运行中的页面继续使用原来已准备的内容。
- 配置管理页的库保存直接落盘。配置编辑器内的库修改和选择先留在草稿，配置最终保存时一次提交；取消编辑不会改动其它配置。
- 删除共享定义会显示与徽标同一口径的已保存配置引用数，确认保存后移除全部引用；仅取消勾选不会删除定义。删除分类只改变组织信息，不影响脚本库和引用数量。
- 名称和地址可编辑；名称留空时使用 URL 解码后的文件名，忽略查询与片段，超过名称上限时截短，无文件名则使用“脚本”。共享 ID 保持稳定。复用统一协议/域名大小写及默认端口，保留路径、查询和片段。导入 JSON 也允许省略名称、使用 null 或留空。
- 脚本库支持批量添加，每行 `脚本名|脚本地址` 或仅填地址。忽略空行，规范化后重复地址跳过并保留原定义，顺序按输入追加；格式错误标注原始行号，整批不添加。单次最多 100 个非空行，仍受脚本库总量 100 个限制。保存及批量添加均不发起网络请求，可用性在打开配置时确认。

## 运行

下载器依次准备启用项及其依赖，然后按引用顺序独立注册。每次打开配置时，启用脚本及其依赖/资源的 UTF-8 字节合计不得超过 16 MiB，超出按脚本准备失败处理并提示。下载/依赖准备失败会汇总脚本名称和原因，等待选择“继续访问”“重试”或“取消”；继续访问只在本次跳过失败脚本，成功脚本正常注册，配置与启用状态均不变。全部失败也可选择仅打开网页。

注册失败、语法错误及顶层启动异常会提示用户是否继续访问。每个脚本的初始化检查独立注册，不依赖 eval/Function，也不依赖 Chromium 对语法错误的 sourceURL 归属；普通 JS 保留全局作用域。各脚本注册源分开，一个错误不会破坏其它脚本或内置交互限制。运行中的失败提示每个脚本每次启动最多一次，普通 GM 网络回调错误和不匹配页面不会反复弹出。

油猴脚本继续各自遵循匹配规则、运行时机与授权。顺序是注册顺序；等待 GM 同步读取快照、不同 `@run-at` 和脚本内部异步任务不会变为串行。只使用现代 `GM.getValue` 的脚本不会等待完整快照，执行后按需读取。脚本存在依赖时仍需自行协调。

每个脚本有独立原生桥、token、GM 网络会话与存储。命令合并显示，前缀为脚本库名称；日志和控制台源也可区分脚本。GM 身份为共享脚本 ID + namespace + name：同一共享脚本跨配置共用 GM 值，不同共享脚本即使 namespace/name 相同仍互相隔离；配置 ID、启用状态和顺序不参与，修改 namespace/name 会换一份 GM 空间。

## 迁移与备份

兼容读取 `version:1` 的单个 `scriptUrl`，迁入库并按地址去重，引用标注 `legacyStorage:true`。首次读取新共享身份时，会在存储后台队列中合并所有引用同一共享脚本的旧配置身份：当前打开的配置优先，其它配置按顺序；不同 key 合并、相同值去重、冲突保留先出现的值，输家来源文件不删除；日志只记录冲突数量、来源和键的不可逆摘要，不记录原始键名或值。合并后超过 10 MiB 则取消并保留全部来源。canonical 文件使用 `AtomicFile` 提交后，仅删除内容已完整包含在其中的旧副本。`legacyStorage:false` 不会读取配置级旧身份。存储文件名继续为 `userscript-values/<64位hash>.json`，新数据与旧备份恢复后的数据使用相同读取路径。

写入和导出采用 `version:2` 的 `scriptLibrary` 与有序 `scripts` 引用。导入替换整份库和配置，拒绝重复定义/引用、非法开关和不存在的脚本 ID。新版备份不能由旧 App 导入；示例见 `config.example.json`。

## 验证

- Kotlin：共享地址变更、顺序/停用、库保留、删除清理所有配置引用、v1 去重迁移、v2 往返、规范化与错误引用；名称留空及 JSON 省略名称；批量解析、重复地址、行号错误和原子提交。
- Node：同一页面的两个油猴脚本各自收发桥消息、读取独立快照并调用正确的菜单。
- Android 15 / WebView 124：同名脚本的样式/存储/菜单隔离，导航与重开，普通 JS 顺序，停用项不下载；下载失败等待选择、继续/重试/取消、全部失败、语法与启动异常的提示及隔离；旧 GM 迁移及再次引用。
- 原生界面：脚本库新建、共享编辑保存/取消、地址复用、选择/上移/停用、编辑草稿重建恢复；留空名称、批量添加及批量错误无部分提交；引用徽标在 0/非零、停用、筛选和回收复用下的数字与样式，窄屏/2 倍字体下整枚换行。
- 分类管理：删除当前分类后配置保留并转为未分类，删除当前筛选分类回落到全部分类且保留收藏，空分类与最后一个分类可删除并隐藏入口；取消确认、未保存名称和保存失败均不改变磁盘内容。480×320dp 横屏下正文需先滚动到删除区再点按；键盘在这类短屏会覆盖大部分对话框，收起后标题与底部操作恢复完整。

注册中途失败会移除之前已注册的句柄并关闭全部脚本 host。这个框架异常清理路径进行了代码核验，未通过真实 WebView 故障注入复现。
